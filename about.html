① 怎么用

学生

  1. 知识地图定位：找到正在学的那一章，看它属于哪条主线。
  2. 课程详解精读：先看学习目标，再读重难点，最后看易错点清单。
  3. 互动实验室动手：每个实验都标了难度星级，核心难点章（★3）优先做。

教师

  1. 投屏讲授：课程详解页一章一节，重难点已用颜色标出等级。
  2. 课堂演示：实验室支持现场改参。让学生先预测，再拖动滑块揭晓。
  3. 布置作业：数据与模型页的数据集可下载 CSV，每个都标注了适用章节。
  4. 随堂小测：自测页按章抽题，含解析，可作为小测或抢答。

③ 修改访问口令

30 秒完成

打开 assets/js/site.js，找到文件开头处的配置区，修改这两行即可：

auth: {
  enabled: true,          // 改成 false 可完全关闭访问闸门
  password: "xwcb2026",   // ← 把这里换成你的口令
  rememberDays: 30        // 「记住我」的有效天数
},
必须了解的安全边界 这是纯前端口令校验，只能挡住「随手点进来的人」，懂技术的人查看源码就能看到口令。 它适合课堂内部使用（防止学生绕过教学内容直接看答案之类），不能用于保护敏感数据。 如果需要真正的账号安全，请见下一节的三种后端方案。

④ 后端登录防护：三种实现

择一即可
先说清楚 JSP 与 PHP 的关系 JSP 是 Java 技术栈（需要 JDK + Tomcat 等容器），PHP 是另一套技术栈（需要 PHP 运行环境）。 两者不能混用，也没有必要混用——它们解决的是同一个问题：在服务器端校验账号密码，未登录不允许访问页面。 选哪一个，取决于你手上有什么服务器。

方案一 · PHP

虚拟主机 / 校园空间首选

绝大多数虚拟主机默认支持 PHP，上传即用，无需配置。

// login.php —— 放在站点根目录
<?php
session_start();

// 账号表：实际使用时把密码散列值存进数据库，不要明文写在这里
$USERS = [
  'student' => '$2y$10$e0NRzS3Uu1yqk8ZQ0m3yQeQ7lJ8yYkz9m2Vv0k9pQ0m3yQeQ7lJ8y',
];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
  $u = isset($_POST['u']) ? trim($_POST['u']) : '';
  $p = isset($_POST['p']) ? $_POST['p'] : '';
  if (isset($USERS[$u]) && password_verify($p, $USERS[$u])) {
    session_regenerate_id(true);        // 防会话固定攻击
    $_SESSION['uid'] = $u;
    $_SESSION['t']   = time();
    header('Location: index.html');
    exit;
  }
  $err = '账号或密码不正确';
}
?>
<!-- 下面是登录表单，省略样式 -->
<form method="post">
  <input name="u" placeholder="账号" required>
  <input name="p" type="password" placeholder="密码" required>
  <button>登录</button>
</form>
// guard.php —— 在每个页面的最顶部 require 一次
<?php
session_start();
$IDLE = 7200;                                   // 2 小时无操作自动登出
if (empty($_SESSION['uid'])
    || (time() - $_SESSION['t']) > $IDLE) {
  header('Location: login.php');
  exit;
}
$_SESSION['t'] = time();                        // 刷新活动时间
?>
用法：把 guard.php 加在所有页面的第一行。 纯静态的 .html 页面若要受保护，可在 .htaccess 里做重写， 或把页面后缀改为 .php 后 require 该守卫文件。

方案二 · Node.js

可一键部署到云

适合把这套静态站直接托管起来，顺便加上真正的鉴权。

// server.js
const express = require('express');
const session = require('express-session');
const bcrypt  = require('bcryptjs');
const app = express();

app.use(express.urlencoded({ extended: false }));
app.use(express.static('.'));                    // 静态资源
app.use(session({
  secret: process.env.SESSION_SECRET || 'change-me',
  resave: false,
  saveUninitialized: false,
  cookie: { httpOnly: true, sameSite: 'lax', maxAge: 2 * 3600 * 1000 }
}));

// 演示用账号；生产环境请改为数据库查询
const USERS = {
  student: bcrypt.hashSync('xwcb2026', 10)
};

// 登录接口
app.post('/api/login', async (req, res) => {
  const { u, p } = req.body;
  const hash = USERS[u];
  if (hash && await bcrypt.compare(p, hash)) {
    req.session.uid = u;
    return res.json({ ok: true });
  }
  res.status(401).json({ ok: false, msg: '账号或密码不正确' });
});

// 守卫：未登录不得访问受保护页面
const PROTECTED = /\.(html?)$/i;
app.use((req, res, next) => {
  if (req.path === '/login.html' || req.path.startsWith('/assets/')
      || req.path.startsWith('/api/')) return next();
  if (PROTECTED.test(req.path) && !req.session.uid) {
    return res.redirect('/login.html');
  }
  next();
});

app.listen(3000, () => console.log('http://localhost:3000'));
依赖：npm i express express-session bcryptjs。 启动：node server.js。

方案三 · JSP + Servlet

需要 JDK + Tomcat

符合你最初提到的 JSP 架构。核心是登录 Servlet 与一个登录过滤器。

<%-- login.jsp --%>
<%@ page contentType="text/html;charset=UTF-8" %>
<form method="post" action="login">
  账号 <input name="u" required>
  密码 <input type="password" name="p" required>
  <button>登录</button>
</form>
// LoginServlet.java
@WebServlet("/login")
public class LoginServlet extends HttpServlet {
  // 演示用；生产环境应查询数据库并存储 BCrypt 散列
  private static final Map<String, String> USERS =
      Map.of("student", "$2a$10$...");

  protected void doPost(HttpServletRequest req, HttpServletResponse resp)
      throws IOException {
    String u = req.getParameter("u");
    String p = req.getParameter("p");
    String hash = USERS.get(u);
    try {
      if (hash != null && BCrypt.checkpw(p, hash)) {
        HttpSession s = req.getSession(true);
        s.setAttribute("uid", u);
        s.setMaxInactiveInterval(7200);          // 2 小时
        resp.sendRedirect("index.html");
        return;
      }
    } catch (Exception ignore) { }
    resp.sendRedirect("login.jsp?err=1");
  }
}
// AuthFilter.java —— 统一拦截，未登录跳登录页
@WebFilter(urlPatterns = {"*.html", "*.jsp"})
public class AuthFilter implements Filter {
  public void doFilter(ServletRequest rq, ServletResponse rs, FilterChain chain)
      throws IOException, ServletException {
    HttpServletRequest  req  = (HttpServletRequest) rq;
    HttpServletResponse resp = (HttpServletResponse) rs;
    String path = req.getRequestURI();
    if (path.endsWith("login.jsp")) { chain.doFilter(rq, rs); return; }
    HttpSession s = req.getSession(false);
    if (s == null || s.getAttribute("uid") == null) {
      resp.sendRedirect(req.getContextPath() + "/login.jsp");
      return;
    }
    chain.doFilter(rq, rs);
  }
}
部署：把网站目录放进 webapp/，编译后由 Tomcat 提供访问。 注意 .html 默认不走 Servlet，需要配置 Filter 映射或在 web.xml 中声明。

共同的安全要点

不管选哪种都适用
  1. 密码不存明文：用 password_hash / bcrypt 等加盐散列。
  2. 登录后重生成会话 ID，防会话固定攻击。
  3. Cookie 加 HttpOnly + SameSite，防脚本窃取与跨站请求伪造。
  4. 限制登录尝试次数，防暴力破解（例如同 IP 5 次失败锁 10 分钟）。
  5. 数据与密钥不进前端：口令、盐值、数据库信息只放服务端。
  6. 设置会话超时并支持主动退出登录。
  7. 强制 HTTPS（公网部署时），避免口令在传输中被截获。
本站现状 目前是纯静态版本，使用前端口令闸门（口令见 第 ③ 节）。 上面的三种后端方案可按需接入；接入后请把 site.js 里的 auth.enabled 改为 false，避免两层验证互相干扰。

⑤ 部署上线

本地直接用 双击 index.html 即可打开（纯静态）。若要避免个别浏览器对本地文件的限制，可在目录下起一个本地服务：
python -m http.server 8000
然后访问 http://localhost:8000。
校园空间 / 虚拟主机 把整个目录（含 assets/）上传到网站根目录即可。若要登录防护，采用 PHP 方案最省事。 注意保持目录结构不变，否则样式与脚本会加载失败。
云服务器 / 容器 若要公网给全班用，建议 Node 方案（node server.js 配合 Nginx 反向代理 + HTTPS 证书）， 或用任意静态托管服务直接上传目录。

⑥ 常见问题

忘记口令了怎么办？向任课老师索取，或按第 ③ 节直接查看/修改源码中的口令。
数据会上传到服务器吗？不会。所有计算都在你的浏览器里完成，实验数据不离开本机。
图表不显示 / 页面错乱？多为浏览器缓存或文件缺失。按 Ctrl+F5 强制刷新；若从服务器访问，确认 assets/ 目录已完整上传。
错题本会同步到其他设备吗？不会，它存在本机浏览器。换设备或清缓存会丢失，重要错题建议另行记录。
可以打印给学生吗？可以。打印时导航栏、侧栏与按钮会自动隐藏，只保留正文内容。
教材章节和本站编号对不上？本站按课程知识体系组织，若与教材目录有出入，以教材为准；可把教材目录发来，按实际章节名对齐。
